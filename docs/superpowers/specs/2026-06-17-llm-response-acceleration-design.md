# 流式优先 + 缓存预热：LLM 响应加速设计

> 日期: 2026-06-17
> 目标: 首字响应 5-8s 以内（当前 15-40s）
> 方案: A(流式优先+路由捷径) + C(缓存预热)

## 背景

当前 Qwen3-8B 单次请求 40s，延迟分布：
- 路由 LLM 分类: 1-4s
- Agent LLM 推理: 15-30s（含重试）
- RAG 检索: 50-500ms（串行在路由之后）

## 优化 1: 路由捷径

**文件**: `router/query_router.py`

当规则分类器产出高置信匹配（confidence >= 0.9）时，跳过 LLM 路由调用。
规则置信 < 0.9 时仍走 LLM 路由，降级行为不变。

预估节省: 1-4s（明确意图查询）

## 优化 2: RAG 预取与路由并行

**文件**: `core/graph_builder.py`

缓存 miss 后，立即启动 RAG 预取任务（用原始查询检索），
与路由分类并行执行。路由结果出来后，Agent 使用已就绪的 RAG 上下文。

预估节省: 50-500ms

## 优化 3: 降低超时 + 减少重试

**文件**: `core/config.py`

- Agent LLM 超时: 30s -> 15s
- 重试次数: 3 -> 2
- 路由 LLM 超时保持 4s

预估节省: 失败场景 15-20s

## 优化 4: 缓存预热

**文件**: `scripts/warm_cache.py`（新）, `api/app_factory.py`

启动时预热 10-20 条通用高频问题（产品成分、使用方法、退换货政策等）。
不预热个性化数据（订单/物流因人而异）。
在 lifespan 中自动执行一次预热。

预估效果: 通用问题 < 0.1s

## 预期效果

| 场景 | 当前 | 优化后首字 | 优化后完整 |
|------|------|-----------|-----------|
| 缓存命中(预热) | 0.004s | <0.1s | <0.1s |
| 明确意图("查订单") | 15-40s | 1-3s | 8-12s |
| 模糊意图 | 15-40s | 3-5s | 10-15s |
| LLM 失败 | 40-90s | - | 15-20s |
