## 二、因果链分析

### 因果链 1：CSP nonce 格式错误

**根因**: `api/middleware.py:168` 缺少 f-string 前缀
  ├→ **症状**: 内联样式被浏览器拒绝
  └→ **症状**: 主题切换异常

**修复建议**: 添加 `f` 前缀
**投入产出**: 1 行代码修复

### 因果链 2：user_id 传递链断裂

**根因**: `llm/client.py:158-167` user_id 未从 metadata 提取
  ├→ **症状**: Token Quota 失效（任何用户都可无限制调用）
  ├→ **症状**: LLM 成本失控
  └→ **症状**: "钱包枯竭攻击"风险

**修复建议**: 注入 user_id 到 metadata
**投入产出**: 3 个文件修改 → 解决所有症状

### 因果链 3：Session 明文存储

**根因**: `core/session/session_manager.py:240-250` 明文 JSON 存储
  ├→ **症状**: PII 泄露风险
  ├→ **症状**: GDPR 不合规
  └→ **症状**: 运维人员可直接读取客户对话

**修复建议**: 引入加密（Fernet / AES-GCM）
**投入产出**: 1 个模块修复 → 解决所有症状

### 因果链 4：DEV_MODE 完全绕过认证

**根因**: `api/middleware.py:241-246` DEV_MODE 跳过所有认证
  ├→ **症状**: WS 认证绕过（A-1）
  └→ **症状**: 开发环境误配置导致生产风险

**修复建议**: 增加启动警告 + 额外确认
**投入产出**: 条件判断修复

## 四、冲突标记

### 冲突 1：添加缓存 vs 数据一致性

| 问题 | 修复建议 | 潜在冲突 |
|------|---------|---------|
| P-1 | 添加 Redis 缓存提升性能 | 可能与 W-3（数据一致性要求）冲突 |

**冲突描述**: 缓存可能导致数据不一致（缓存与数据库不同步）
**协调方案**:
- 方案 A：添加缓存失效策略（写入时失效 + TTL）
- 方案 B：使用写透缓存（Write-Through）
- 方案 C：放弃缓存，改用数据库索引优化

**推荐**: 方案 A（缓存失效策略），投入最小，风险可控

### 冲突 2：加密 Session vs 性能

| 问题 | 修复建议 | 潜在冲突 |
|------|---------|---------|
| H-2 | 加密 Session 存储 | 可能影响读写性能 |

**冲突描述**: 加密/解密操作增加 CPU 开销
**协调方案**:
- 方案 A：仅加密敏感字段（PII），非全量加密
- 方案 B：使用硬件加速（AES-NI）
- 方案 C：改用数据库原生加密（TDE）

**推荐**: 方案 A（部分加密），投入最小，风险可控
